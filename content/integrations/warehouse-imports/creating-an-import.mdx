An import reads a table or SQL query from a [connected warehouse](/integrations/warehouse-imports/connecting-a-warehouse) and writes each row into one environment in Knock.

To create one, go to **Platform** > **Imports** in the environment you want to import into and click **Create import**. You can also click **Create import** on a connected warehouse's page, which opens the editor with that warehouse already chosen.

The editor has six steps.

## 1. Details

- **Name** is how the import appears in Knock.
- **Key** identifies the import. It follows the name until you edit it, and can't be changed after the import is created.
- **Imports into** sets the target: **Users**, **Tenants**, **Objects**, or **Audience members**. It can't be changed later.
  - For objects, enter the **Collection** every row is written to.
  - For audience members, choose the static **Audience** every row adds a member to.

## 2. Source

Choose the **Warehouse** to read from, then what to read:

- **Table or view.** Search for and pick a table or view.
- **SQL query.** Write a query and click **Preview query**. Use a query to filter rows, join tables, or convert column types before Knock reads them. See [data types](#data-types).

The warehouse can't be changed after the import is created.

## 3. Preview

Knock shows sample rows from the table or query exactly as your warehouse returns them. The mapping step uses these rows, so the columns to map only appear once there's a preview.

## 4. Map columns

### Primary key

Choose the column that uniquely identifies each row. For users, tenants, and objects, its value becomes the record's ID in Knock, so it must be a non-empty string of at most 256 characters with no `/`.

### Columns

Each column in the source has a row in the mapping table, with sample values from the preview. Check a column to import it, then choose its **Knock field**:

| Target  | Standard fields                                         |
| ------- | ------------------------------------------------------- |
| Users   | `name`, `email`, `phone_number`, `avatar`, `created_at` |
| Tenants | `name`                                                  |
| Objects | `name`                                                  |

Any other field name becomes a custom property. Field names can contain letters, numbers, and underscores, and can't start with a number. For users, the field list also suggests properties your existing users already have.

A column that holds a JSON object can be mapped whole as one property, or each of its keys can be mapped to its own field.

**When null** sets what happens when a row's value for a column is null:

- **Clear value** sets the field to null in Knock. This is the default.
- **Keep current value** leaves the field as it is in Knock.

Columns you don't check are never changed on existing records.

### Audience members

Audience imports don't use the mapping table. Choose:

- **User ID column.** Each row adds the user with this ID to the audience.
- **Tenant column.** Optional. Adds the member for this tenant only. Leave it empty for audiences without tenants.

The primary key for an audience import identifies the row so Knock can find changed rows. It isn't written to the audience.

## 5. Change detection

Both columns are optional.

- **Last modified column.** A timestamp column that updates whenever a row changes. Each sync reads only the rows that changed since the last sync. Without it, each sync reads the whole source and Knock compares it with the previous sync to find changed rows, which is slower for large tables.
- **Deleted flag column.** A true or false column. Rows where it's true are skipped, so Knock keeps what it already has for them.

## 6. Schedule

Choose how often Knock syncs once the import is published: every 10 minutes, 15 minutes, hour, 6 hours, 12 hours, or day. You can change the frequency or pause the import later from its **Settings** tab.

## Save and publish

- **Save draft** (or **Save** on an existing import) saves a new version without changing what's live.
- **Save and publish** saves a new version and makes it live. Knock starts syncing on the import's schedule.

Before publishing, Knock checks the preview rows against the fields they map to. A mapping that would make Knock reject rows is marked in red and blocks **Save and publish** until you fix it. **Save** still works, so you can keep a draft. The check covers:

- Primary key values that are empty, longer than 256 characters, or contain `/`.
- A user's `created_at` value without a timezone.

Publishing takes a moment. The import shows **Publishing** until it's live, and **Delivery failed** with the error and a **Retry delivery** button if it doesn't go live.

## Data types

Knock reads column values as your warehouse returns them. Convert types in a SQL query when a column doesn't match the Knock field it maps to.

### Timestamps

A user's `created_at` must be a date and time with a timezone, such as `2026-09-26T20:19:49Z`.

- **Redshift.** `TIMESTAMP` columns have no timezone, so Knock rejects every row that maps one to `created_at`. Convert the column in your query:

  ```sql
  SELECT
    user_id,
    email,
    TO_CHAR(created_at, 'YYYY-MM-DD"T"HH24:MI:SS"Z"') AS created_at
  FROM analytics.dim_users
  ```

  This writes the value as UTC. If your timestamps aren't stored in UTC, convert them first with `CONVERT_TIMEZONE`.

- **Snowflake.** Timestamp columns, including `TIMESTAMP_NTZ`, can be mapped to `created_at` directly.

- **Text columns.** A text value must already include a timezone, such as a `Z` or `+00:00` offset.

### IDs

Record IDs are strings. If your ID column is a number, cast it in your query, such as `CAST(account_id AS VARCHAR)`.
