Warehouse syncs read a table or SQL query in your data warehouse on a schedule and write the rows into Knock. Use them to keep your users, tenants, and other recipient data in Knock up to date from your warehouse.

To send Knock's notification data to your warehouse instead, see [data warehouse sync](/integrations/extensions/data-sync).

## How warehouse syncs work

1. **Connect a warehouse.** Add your warehouse once from **Platform** > **Sources**. Every environment in your account can sync from it. See [connecting a warehouse](/integrations/warehouse-syncs/connecting-a-warehouse).
2. **Create a sync.** A sync reads a table or SQL query and writes each row to Knock in one environment. You choose how columns map to Knock fields and how often it runs. See [creating a sync](/integrations/warehouse-syncs/creating-a-sync).

When you publish a sync, it runs once right away and then on its schedule. Each run applies only the rows that changed since the last run. See [managing syncs](/integrations/warehouse-syncs/managing-syncs).

## Supported warehouses

| Warehouse       | How Knock connects                             |
| --------------- | ---------------------------------------------- |
| Amazon Redshift | An IAM role Knock assumes                      |
| Snowflake       | Key-pair authentication                        |
| PostgreSQL      | A database user and password                   |
| Google BigQuery | A service account in your Google Cloud project |
| Databricks      | Coming soon                                    |

If you'd like us to support a warehouse that isn't listed, let us know at [support@knock.app](mailto:support@knock.app?subject=Warehouse%20syncs).

## What you can sync

Each sync writes to one of these:

| Target           | What each row does                                                           |
| ---------------- | ---------------------------------------------------------------------------- |
| Users            | Creates or updates a [user](/concepts/users).                                |
| Tenants          | Creates or updates a [tenant](/concepts/tenants).                            |
| Objects          | Creates or updates an [object](/concepts/objects) in one collection.         |
| Audience members | Adds a user to a static [audience](/concepts/audiences).                     |
| Subscriptions    | [Subscribes](/concepts/subscriptions) a user to an object in one collection. |

Knock only changes the fields you map. Tenant syncs set a tenant's name and custom properties, not its settings such as branding.

## Deleted rows

What happens when a row is deleted depends on what the sync writes to.

**Subscriptions and audience members.** When a row is deleted from your warehouse or no longer matches your query, Knock unsubscribes the user from the object or removes them from the audience. You can also use a [deleted flag column](/integrations/warehouse-syncs/creating-a-sync#5-change-detection) to mark rows to remove. If the sync has a last modified column, Knock only sees rows that changed, so use a deleted flag column instead of deleting rows.

**Users, tenants, and objects.** Deleting a row doesn't delete the record in Knock. To delete records, add a deleted flag column and a last modified column to the sync. Knock deletes the records for rows where the flag is true. This can't be undone.

## Environments

A warehouse is shared by every environment in your account. A sync belongs to one environment, so you can sync into Development and Production separately from the same warehouse. To copy a sync into another environment, [clone it](/integrations/warehouse-syncs/managing-syncs#clone-a-sync).

Syncs aren't part of the commit and promote flow. You create and edit a sync in the environment it syncs into, including Production. Each published version is listed on the sync's **Changes** tab, where you can revert to an earlier one. Syncs aren't available in branch environments.

## Permissions

| Action                                  | Built-in roles       | Custom permission groups  |
| --------------------------------------- | -------------------- | ------------------------- |
| Add, edit, test, and archive warehouses | Owner, Admin         | Can manage integrations   |
| View warehouses and syncs               | Owner, Admin, Member | Can view recipient data   |
| Create and manage syncs                 | Owner, Admin, Member | Can manage recipient data |

To open the **Sources** page, a custom permission group must also be allowed to view integrations. Recipient data permissions are set per environment, so a group can manage syncs in Development and only view them in Production. See [roles and permissions](/manage-your-account/roles-and-permissions).
