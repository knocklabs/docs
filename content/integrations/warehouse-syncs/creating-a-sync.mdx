A sync reads a table or SQL query from a [connected warehouse](/integrations/warehouse-syncs/connecting-a-warehouse) and writes each row into one environment in Knock.

To create one, switch to the environment you want to sync into, go to **Platform** > **Sources**, open the warehouse, and click **Create sync**. The editor has six steps.

## 1. Details

- **Name** is how the sync appears in Knock.
- **Key** identifies the sync. It can't be changed after the sync is created.
- **Syncs to** is what each row writes to: **Users**, **Tenants**, **Objects**, **Audience members**, or **Subscriptions**. It can't be changed later.
  - For objects, enter the **Collection** to write to.
  - For subscriptions, enter the **Collection** of the objects users subscribe to. It defaults to `$tenants`.
  - For audience members, choose a static **Audience**.

A sync writes to one collection. To sync several collections, create a sync for each and filter its rows with a `WHERE` clause in a SQL query.

## 2. Source

Choose what the sync reads:

- **Table or view** reads one table or view. If a table you just created isn't listed, click **Refresh tables**.
- **SQL query** reads the result of a query. Write the query and click **Preview query**. Use a query to filter rows, join tables, rename columns, or convert types. See [data types](#data-types).

If the [Knock agent](/ai/agent) is available in your account, click **Ask agent** to have it write the query, or **Ask agent to fix** when a preview fails.

## 3. Preview

Knock shows the first 20 rows as your warehouse returns them. You map columns from this preview in the next step.

## 4. Map columns

### Primary key

Choose the column that uniquely identifies each row. Knock uses it to find rows that changed.

For users, tenants, and objects, the primary key is also the record's ID in Knock. It must be a non-empty string of at most 256 characters with no `/`.

For subscriptions and audience members, the primary key only identifies the row. For audience members, it's usually the user ID column. If no single column is unique, build one in a SQL query, such as `account_id || ':' || user_id`.

### Columns

Check each column you want to sync, or check **Sync all columns**. Then choose its **Knock field**:

| Target  | Standard fields                                         |
| ------- | ------------------------------------------------------- |
| Users   | `name`, `email`, `phone_number`, `avatar`, `created_at` |
| Tenants | `name`                                                  |
| Objects | `name`                                                  |

Any other field name becomes a custom property. Field names can contain letters, numbers, and underscores, and can't start with a number.

A column that holds a JSON object can be mapped as one property, or each of its keys can be mapped to its own field.

**When null** sets what happens when a row's value is null:

- **Clear the field** removes the value in Knock. This is the default.
- **Keep Knock's value** leaves the value in Knock as it is.

Columns you don't check are never changed in Knock.

### Audience members

Audience syncs don't use the mapping table. Choose:

- **User ID column.** The user each row adds to the audience.
- **Tenant column.** Optional. Adds the user for this tenant only.

To update these users' names, emails, or properties, create a users sync from the same query.

While a published sync manages an audience, its members can't be changed any other way, including from the dashboard or the API. This applies even while the sync is paused.

### Subscriptions

Choose:

- **Object ID column.** The object in the sync's collection that the user subscribes to.
- **User ID column.** The user who subscribes.

Knock creates the user or object if it doesn't exist yet, with no name or properties. Any other columns you check become properties on the subscription. To sync the objects' names and properties, create an objects sync.

## 5. Change detection

Both columns are optional. With neither, each run reads the whole source and compares it with the last run to find what changed. That works for most tables.

- **Last modified column.** A timestamp column that updates whenever a row changes. Each run reads only rows changed since the last run, which speeds up large tables. Knock can't see rows deleted from the source, so use a deleted flag column to remove them.
- **Deleted flag column.** A true or false column that marks rows to remove. Flagged rows unsubscribe the user from the object, remove the member from the audience, or delete the user, tenant, or object from Knock. Deleting a user, tenant, or object can't be undone. For those syncs, a deleted flag column needs a last modified column.

See [deleted rows](/integrations/warehouse-syncs/overview#deleted-rows).

## 6. Schedule

Choose how often the sync runs: every 10 minutes, 15 minutes, hour, 6 hours, 12 hours, or day. You can change this or pause the sync later from its **Settings** tab.

## Save and publish

- **Save draft** saves the sync without running it.
- **Save and publish** saves the sync and makes it live. A new sync runs once right away, then on its schedule.

Before publishing, Knock checks the preview rows. **Save and publish** is blocked, and the problem is marked in red, when:

- A primary key value is empty, longer than 256 characters, or contains `/`.
- A user's `created_at` value has no timezone. See [timestamps](#timestamps).

**Save draft** still works.

The sync shows **Publishing** until it's live. If it doesn't go live, it shows **Delivery failed** with the error and a **Retry delivery** button.

## Data types

Knock reads values as your warehouse returns them. Convert types in a SQL query when a column doesn't match its Knock field.

### Timestamps

A user's `created_at` must include a timezone, such as `2026-09-26T20:19:49Z`.

- **Redshift and PostgreSQL.** `TIMESTAMP` columns have no timezone, so Knock rejects rows that map one to `created_at`. Convert it in your query. For timestamps stored in UTC:

  ```sql
  -- Redshift
  SELECT user_id, email, created_at::TIMESTAMPTZ AS created_at
  FROM analytics.dim_users

  -- PostgreSQL
  SELECT user_id, email, created_at AT TIME ZONE 'UTC' AS created_at
  FROM public.users
  ```

  For timestamps stored in another time zone, name it: `CONVERT_TIMEZONE('America/New_York', 'UTC', created_at)::TIMESTAMPTZ` in Redshift, or `created_at AT TIME ZONE 'America/New_York'` in PostgreSQL. `TIMESTAMPTZ` columns can be mapped directly.

- **Snowflake.** Timestamp columns, including `TIMESTAMP_NTZ`, can be mapped directly.
- **Text columns.** The value must include a timezone, such as `Z` or `+00:00`.

### IDs

Record IDs are strings. If your ID column is a number, cast it in your query, such as `CAST(account_id AS VARCHAR)`.
