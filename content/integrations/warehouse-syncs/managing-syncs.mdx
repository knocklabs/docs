To find a sync, go to **Platform** > **Sources** in the environment it syncs into and open its warehouse. The **Syncs** tab lists the warehouse's syncs with their status and last run.

A sync's page has four tabs:

- **Overview** shows the sync's recent and next runs and its current setup.
- **Runs** lists recent runs.
- **Settings** has the schedule and the option to archive the sync.
- **Changes** lists each published version.

## Sync statuses

| Status          | Meaning                                                                     |
| --------------- | --------------------------------------------------------------------------- |
| Draft           | Saved but never published, so it doesn't run.                               |
| Publishing      | Knock is making the published version live.                                 |
| Delivery failed | The published version didn't go live. Click **Retry delivery** on the sync. |
| Live            | Runs on its schedule.                                                       |
| Needs attention | The last run failed. The sync keeps running on its schedule.                |
| Paused          | Published, but doesn't run until you resume it.                             |

## Run a sync now

Click **Run now** on a published sync to run it right away. If a run is already in progress, Knock doesn't start another.

## Pause and resume

Click **Pause** on the sync, or turn off **Run on schedule** on its **Settings** tab. A run that has already started finishes. Click **Resume** to start running on the schedule again.

## Change the schedule

On the sync's **Settings** tab, change the **Frequency**. Schedule changes apply right away and don't create a new version.

## Edit a sync

On the sync's **Overview** tab, click the edit button on the section you want to change: **Details**, **Source**, **Mappings**, or **Change detection**. The key, target, and warehouse can't be changed.

Click **Save** to save a new version. The sync shows **Unpublished changes** until you click **Publish**.

When you publish a change to the table or query, the primary key, or a change detection column, the next run reads every row in the source again. Rows removed from the source before that run aren't treated as deleted.

## Version history

The **Changes** tab lists every published version of the sync, newest first, with who published it and when. Click the revert button on a version to publish it again as a new version. You can revert in any environment, including Production.

## Clone a sync

Click **Clone** on a sync to copy its source, mappings, and schedule into a new sync. The copy can go in the same environment or another one.

Enter a name and key for the copy, and choose the warehouse it reads from. For object and subscription syncs, you can change the collection. For audience syncs, choose an audience in the environment you're cloning into.

The copy includes the sync's unpublished changes. It starts as a draft, with no runs.

## Archive a sync

On the sync's **Settings** tab, click **Archive sync**. Knock stops running the sync, and its key can be used again. Records it already wrote stay in Knock. This can't be undone.

## Run history

The sync's **Runs** tab lists its 25 most recent runs, with when each started, its status, and how many rows were read and failed. The warehouse's **Runs** tab lists the 25 most recent runs across all its syncs, and you can filter it by sync or status.

| Status                | Meaning                                    |
| --------------------- | ------------------------------------------ |
| Running               | The run is in progress.                    |
| Completed             | Every changed row was applied.             |
| Completed with errors | Some rows were applied and some weren't.   |
| Failed                | The run stopped. The run details show why. |

Each run only applies rows that changed since the last run. A run that finds no changes applies nothing.

### Run details

Click a run to see its details:

- **Rows read**, **Rejected**, **Applied**, and **Failed**. Rejected rows never reached Knock. Failed rows reached Knock but couldn't be saved.
- For a failed run, where it stopped and the error.
- **Rejected rows** and **Failed rows**, with a sample of each grouped by error, and the primary keys each error affected.
- The batches Knock received. Large runs arrive in several batches, which Knock applies in order.

## When a run fails

The sync shows **Needs attention**, and its **Overview** tab says why the last run failed. If the warehouse's connection works, the warehouse also shows **Needs attention** on the **Sources** page. The sync keeps running on its schedule, and the status clears after a run succeeds.

## Troubleshooting

| Problem                                          | What to check                                                                                                                                                            |
| ------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| A table is missing from the table picker         | Click **Refresh tables**. If it's still missing, check the database user's grants.                                                                                       |
| The preview or a run fails reading the source    | That the database user can read every table the query uses.                                                                                                              |
| Every row is rejected                            | A type mismatch, most often a Redshift or PostgreSQL `TIMESTAMP` mapped to `created_at`. See [timestamps](/integrations/warehouse-syncs/creating-a-sync#timestamps).     |
| Some rows are rejected or failed                 | The **Rejected rows** and **Failed rows** on the run. Fix or filter those rows in a SQL query.                                                                           |
| A record is still in Knock after its row is gone | See [deleted rows](/integrations/warehouse-syncs/overview#deleted-rows). If the sync has a last modified column, set the row's deleted flag instead of deleting the row. |
| No runs appear                                   | That the sync is published and not paused. Click **Run now** to run it without waiting.                                                                                  |
