## Message events

<Callout
  emoji="💡"
  text={
    <>
      The <code>event_data</code> field is event-specific and will be{" "}
      <code>null</code> when not applicable. When present, its available fields
      and content may vary by channel provider.
    </>
  }
/>

<AccordionGroup>
  <Accordion title="`message.sent`" anchorSlug="messagesent">
    Occurs when a message is successfully sent to a channel provider.

    <Attributes>
      <Attribute
        name="data"
        type="Message"
        description="The associated message."
        typeSlug="/api-reference/messages/schemas/message"
      />
    </Attributes>

  </Accordion>
  <Accordion title="`message.delivered`" anchorSlug="messagedelivered">
    Occurs when a message is marked as delivered to the user by the provider. Not all channels support delivery tracking. Reference the docs on the [`delivered` message status](/send-notifications/message-statuses#7-delivered) to see which channels and providers are supported.

    <Attributes>
      <Attribute
        name="data"
        type="Message"
        description="The associated message."
        typeSlug="/api-reference/messages/schemas/message"
      />
    </Attributes>

  </Accordion>
  <Accordion title="`message.delivery_attempted`" anchorSlug="messagedelivery_attempted">
    Occurs when a message delivery attempt fails and may be retried.

    <Attributes>
      <Attribute
        name="data"
        type="Message"
        description="The associated message."
        typeSlug="/api-reference/messages/schemas/message"
      />
      <Attribute
        name="event_data"
        type="EventData"
        description="Additional information about the attempt, the total attempts, and whether or not it will be retried."
        expandLabel="EventData attributes"
      >
        <Attributes>
          <Attribute
            name="attempt"
            type="number"
            description="The current attempt count."
          />
          <Attribute
            name="max_attempts"
            type="number"
            description="The total number of attempts that can be tried."
          />
          <Attribute
            name="retryable"
            type="boolean"
            description="Whether or not the current attempt is retryable. This field may be absent if retryability is not
      determined."
          />
        </Attributes>
      </Attribute>
    </Attributes>

  </Accordion>
  <Accordion title="`message.undelivered`" anchorSlug="messageundelivered">
    Occurs when a message delivery attempt fails permanently. Delivery will not be retried.

    <Attributes>
      <Attribute
        name="data"
        type="Message"
        description="The associated message."
        typeSlug="/api-reference/messages/schemas/message"
      />
      <Attribute
        name="event_data"
        type="EventData"
        description="May include additional information about the failure."
        expandLabel="EventData attributes"
      >
        <Attributes>
          <Attribute
            name="failure_reason"
            type="string"
            description="The reason for a message failure. One of `fatal_error` or `retries_exhausted`."
          />
          <Attribute
            name="failure_details"
            type="string"
            description="Details about a message failure. This field varies by provider and is nullable."
          />
        </Attributes>
      </Attribute>
    </Attributes>

  </Accordion>
  <Accordion title="`message.bounced`" anchorSlug="messagebounced">
    Occurs when a message delivery attempt fails due to bounce or a delivery status check results in a bounce because of a bad recipient(s) identifier. Delivery will not be retried.

    <Attributes>
      <Attribute
        name="data"

          <Attribute
            name="failure_details"
            type="string"

          />
          <Attribute
            name="token"
            type="string"
            description="The erroneous token causing the bounce. Only applicable for push messages."

        </Attributes>
      </Attribute>
    </Attributes>

  </Accordion>

Only available on select email providers with [delivery status webhooks](/send-notifications/delivering-notifications#delivery-status-tracking) configured to send complaint events: [Postmark](/integrations/email/postmark#complaint-events), [Resend](/integrations/email/resend#complaint-events), [AWS SES](/integrations/email/aws-ses#complaint-events), [SendGrid](/integrations/email/sendgrid#complaint-events), and [Mailgun](/integrations/email/mailgun#complaint-events).

## Workflow run events

Use these events to respond when a recipient's workflow run starts, completes, or encounters an error. You can also inspect runs via the [workflow recipient runs API](/api-reference/workflow_recipient_runs).

## Commit events

[Promoting commits](/version-control/commits#promoting-commits) copies them from one [environment](/version-control/environments) into another, and [merging a branch](/version-control/branches#merging-changes-from-a-branch) promotes its commits into the parent environment. Use these events to respond when changes land in an environment. You can also inspect promotes via the [list commits endpoint](/mapi-reference/commits/list). Publishing a change creates a commit, and Knock sends a `*.committed` event for that commit.

<AccordionGroup>
  <Accordion title="`commits.promoted`" anchorSlug="commitspromoted">
    Occurs whenever commits are promoted into an environment, including when a branch is merged. Knock sends one event per promote to webhooks in the destination environment. Promoted commits don't send `*.committed` events. Learn more about [reacting to promotes](/version-control/commits#reacting-to-promotes).

    <Attributes>
      <Attribute
        name="data"
        type="PromoteGroup"
        description="The associated promote group. Use its `id` to list the commits the promote created."
        typeSlug="/mapi-reference/commits/schemas/promote_group"
      />
    </Attributes>

  </Accordion>
</AccordionGroup>

## Branch events

Knock sends branch events to webhooks in the branch's parent environment. Merging a branch sends [`commits.promoted`](#commitspromoted) with a `source_type` of `branch`, not a separate merge event.

<AccordionGroup>
  <Accordion title="`branch.created`" anchorSlug="branchcreated">
    Occurs whenever a branch is created.

    <Attributes>
      <Attribute
        name="data"
        type="BranchEventData"
        description="The associated branch and the user who created it."
        expandLabel="BranchEvent attributes"
      >
        <Attributes>
          <Attribute
            name="branch"
            type="object"
            description="The branch's `slug`, `name`, `parent_environment`, and `created_at`."
          />
          <Attribute
            name="actor"
            type="object | null"
            description="The name and email of the user who created the branch. Null when no user is associated with the event."
          />
        </Attributes>
      </Attribute>
    </Attributes>

  </Accordion>
  <Accordion title="`branch.deleted`" anchorSlug="branchdeleted">

      >

          <Attribute
            name="actor"
            type="object | null"

        </Attributes>

  </Accordion>
  <Accordion title="`branch.rebased`" anchorSlug="branchrebased">

            description="The name and email of the user who rebased the branch. Null when no user is associated with the event."

## Resource events

Knock sends a `*.updated` event when a resource changes in an environment and a `*.committed` event when that change is committed. Committed events include the commit ID in `event_data`. Goals publish on save, so they send only `goal.updated`, which carries the commit ID.
