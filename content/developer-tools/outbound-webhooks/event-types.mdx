## Message events

<Callout
  emoji="💡"
  text={
    <>
      The <code>event_data</code> field is event-specific and will be{" "}
      <code>null</code> when not applicable. When present, its available fields
      and content may vary by channel provider.
    </>
  }
/>

### `message.sent`

Occurs when a message is successfully sent to a channel provider.

<Attributes>
  <Attribute
    name="data"
    type="Message"
    description="The associated message."
    typeSlug="/api-reference/messages/schemas/message"
  />
</Attributes>

### `message.delivered`

Occurs when a message is marked as delivered to the user by the provider. Not all channels support delivery tracking. Reference the docs on the [`delivered` message status](/send-notifications/message-statuses#7-delivered) to see which channels and providers are supported.

<Attributes>
  <Attribute
    name="data"
    type="Message"
    description="The associated message."
    typeSlug="/api-reference/messages/schemas/message"
  />
</Attributes>

### `message.delivery_attempted`

Occurs when a message delivery attempt fails and may be retried.

<Attributes>
  <Attribute
    name="data"
    type="Message"
    description="The associated message."
    typeSlug="/api-reference/messages/schemas/message"
  />
  <Attribute
    name="event_data"
    type="EventData"
    description="Additional information about the attempt, the total attempts, and whether or not it will be retried."
    expandLabel="EventData attributes"
  >
    <Attributes>
      <Attribute
        name="attempt"
        type="number"
        description="The current attempt count."
      />
      <Attribute
        name="max_attempts"
        type="number"
        description="The total number of attempts that can be tried."
      />
      <Attribute
        name="retryable"
        type="boolean"
        description="Whether or not the current attempt is retryable. This field may be absent if retryability is not
  determined."
      />
    </Attributes>
  </Attribute>
</Attributes>

### `message.undelivered`

Occurs when a message delivery attempt fails permanently. Delivery will not be retried.

<Attributes>
  <Attribute
    name="data"
    type="Message"
    description="The associated message."
    typeSlug="/api-reference/messages/schemas/message"
  />
  <Attribute
    name="event_data"
    type="EventData"
    description="May include additional information about the failure."
    expandLabel="EventData attributes"
  >
    <Attributes>
      <Attribute
        name="failure_reason"
        type="string"
        description="The reason for a message failure. One of `fatal_error` or `retries_exhausted`."
      />
      <Attribute
        name="failure_details"
        type="string"
        description="Details about a message failure. This field varies by provider and is nullable."
      />
    </Attributes>
  </Attribute>
</Attributes>

### `message.bounced`

Occurs when a message delivery attempt fails due to bounce or a delivery status check results in a bounce because of a bad recipient(s) identifier. Delivery will not be retried.

<Attributes>
  <Attribute
    name="data"
    type="Message"
    description="The associated message."
    typeSlug="/api-reference/messages/schemas/message"
  />
  <Attribute
    name="event_data"
    type="EventData"
    description="May include additional information about the failure."
    expandLabel="EventData attributes"
  >
    <Attributes>
      <Attribute
        name="failure_reason"
        type="string"
        description="The reason for a message failure."
      />
      <Attribute
        name="failure_details"
        type="string"
        description="Details about a message bounce."
      />
      <Attribute
        name="token"
        type="string"
        description="The erroneous token causing the bounce. Only applicable for push messages."
      />
    </Attributes>
  </Attribute>
</Attributes>

### `message.complaint`

Occurs when a recipient reports a delivered email as spam and the email provider relays the complaint to Knock. A complaint is a post-delivery event, so it does not change the message's delivery status. Only available on select email providers with [delivery status webhooks](/send-notifications/delivering-notifications#delivery-status-tracking) configured to send complaint events: [Postmark](/integrations/email/postmark#complaint-events), [Resend](/integrations/email/resend#complaint-events), [AWS SES](/integrations/email/aws-ses#complaint-events), [SendGrid](/integrations/email/sendgrid#complaint-events), and [Mailgun](/integrations/email/mailgun#complaint-events).

<Attributes>
  <Attribute
    name="data"
    type="Message"
    description="The associated message."
    typeSlug="/api-reference/messages/schemas/message"
  />
  <Attribute
    name="event_data"
    type="EventData"
    description="Includes a subset of the provider's complaint payload, such as the complained recipient address and the provider's complaint timestamp. The available fields vary by provider."
  />
</Attributes>

## Workflow recipient run events

A [workflow recipient run](/concepts/workflows#workflow-runs-and-recipients) represents the execution of a workflow for a single recipient. Use these events to respond when a recipient's workflow run starts, completes, or encounters an error. You can also inspect runs via the [workflow recipient runs API](/api-reference/workflow_recipient_runs).

### `workflow_recipient_run.started`

Occurs when a workflow recipient run begins execution.

## Commit events

<Callout
  type="beta"
  title="Beta feature."
  text={
    <>
      Commit webhooks are currently in beta and enabled on an on-demand basis.
      To request access for your account,{" "}
      <a href="mailto:support@knock.app?subject=Commit webhooks">
        get in touch
      </a>
      .
    </>
  }
/>

[Promoting commits](/version-control/commits#promoting-commits) copies them from one environment into another, and [merging a branch](/version-control/branches#merging-changes-from-a-branch) promotes its commits into the parent environment. Use these events to respond when changes land in an environment. You can also inspect promotes via the [list commits endpoint](/mapi-reference/commits/list).

### `commits.promoted`

Occurs whenever commits are promoted into an environment, including when a branch is merged. Knock sends one event per promote to webhooks in the destination environment. Promoted commits don't send `*.committed` events. Learn more about [reacting to promotes](/version-control/commits#reacting-to-promotes).

<Attributes>
  <Attribute
    name="data"
    type="PromoteGroup"
    description="The associated promote group. Use its `id` to list the commits the promote created."
    typeSlug="/mapi-reference/commits/schemas/promote_group"
  />
</Attributes>

## Branch events

<Callout
  type="beta"
  title="Beta feature."
  text={
    <>
      Branch webhooks are currently in beta and enabled on an on-demand basis.
      To request access for your account,{" "}
      <a href="mailto:support@knock.app?subject=Branch webhooks">
        get in touch
      </a>
      .
    </>
  }
/>

A [branch](/version-control/branches) isolates changes to your resources from its parent environment until you merge them. Use these events to respond when a branch is created, rebased, or deleted. Knock sends branch events to webhooks in the branch's parent environment. Merging a branch sends [`commits.promoted`](#commitspromoted) with a `source_type` of `branch`.

Occurs whenever a branch is created.

        name="actor"
        type="object | null"
        description="The name and email of the user who created the branch. Null when no user is associated with the event."

    </Attributes>
  </Attribute>
</Attributes>
